# 「足さない練習」進行ガイド

[スライド原稿](../slides/2026/60min-practice-not-adding.md) ／ [公開PDF](../slides/2026/60min-practice-not-adding.pdf)

## 対象と持ち帰るもの

開発経験の少ない学生を対象とする、60分の個人ワークです。前半で判断の構造を説明し、後半で題材を選んで使います。題材は「自分が最近経験した選択」または「主催者が用意する共通事例」。開発経験、AIのアカウント、画面作成の技能は必要ありません。

中心の問いは「何を足し、何を見送るかを、どう決めるか」です。AIに実装のたたき台を頼めることを入口に、道具・教材・予定などの身近な選択へ広げます。持ち帰るものは、選択と理由、引き受ける負担、次に確かめることを残した四欄のメモです。機能や持ち物の少なさを評価するワークではありません。

## 先に説明する構造

**場面 → 目的と条件 → 選択肢の比較 → 確かめ方**

これは作業の担当順ではなく、判断の根拠をつなぐ構造です。具体的な場面から目的を考え、目的と守る条件を比較の基準にします。候補それぞれの効果と負担を比べて案を選び、その目的に合うか確かめます。新しく分かったことから、目的や選択を見直します。

| 欄 | 考える問い | 次の判断へ渡すもの |
| --- | --- | --- |
| ① 場面 | なぜ選ぶ必要があったか。何が分かっていたか。 | 選択が必要になった出来事と、まだ不明な点。 |
| ② 目的と条件 | どうなりたいか。何を失うと困るか。 | 比較と確認に使う基準。できれば欲しいことと、必ず守ることの区別。 |
| ③ 選択肢 | 同じ基準で二案を比べると、何を得て、どんな負担を引き受けるか。 | 選んだ案、理由、見送るもの、未確認の前提。 |
| ④ 確かめ方 | 何を見れば役立ったと分かるか。どんな結果なら選び直すか。 | 次の試行と、判断を見直す条件。 |

最初の24分では、教材や予定表の場面から、この構造を説明します。実際に起きたこと、考えた理由、まだ分からないことを確かめてから、次の問いへ進みます。説明用の例を参加者全員の題材にはしません。四つの問いは三冊の見方を応用した本ワークショップ独自の整理であり、特定の書籍に載っている手法名や手順ではありません。

本編では「誰がそう言ったか」よりも、「この場面なら何を確かめたいか」を先に説明します。出典は脚注に置き、専門用語や書籍の著者の経験は補足で紹介します。たとえば、認知負荷は入力先・修正箇所・覚える操作の話として、判断の来歴は選んだ理由とその条件を残す話として伝えます。

### 前提を確かめる順序

| 説明すること | 先にそろえる前提 | 使う例と戻る場所 |
| --- | --- | --- |
| 目的と手段 | 起きたことと、理由の推測は別である。 | 5〜8頁で、教材の一行が分からない場面から、目的と方法を分ける。 |
| 条件と不明点 | できるようになりたいことに加え、使える時間や変えない予定がある。 | 12〜16頁で、曖昧な依頼を具体化し、30分取り組む予定と30分で終わる見込みを分ける。 |
| 追加と置き換え | 道具は、使う間の入力・修正や、ほかの情報とのつながりを持つ。 | 19〜22頁で、二つの予定アプリと、古いメモにしかない情報を見る。 |
| 確認と見直し | 完成したことと、使う人が助かったことは異なる。 | 23〜28頁で、確認する項目、一つの試行、結果が成り立つ条件を分ける。 |
| 判断理由の記録 | ある条件で選んだ案が、別の条件でも合うとは限らない。 | 29〜30頁で教材の例に戻り、31頁で四つの問いのつながりを再確認する。 |

### 説明で掘り下げる論点

| 論点 | なぜ判断に関わるか | 成り立つ条件と、ワークへの接続 |
| --- | --- | --- |
| 目的と手段を分ける | 最初に思いついた手段だけを比べると、今あるものを使う別案が消える。手段が役立つには時間や情報なども必要になる。 | 新しいものを使う方が目的に合う場合もある。①から②を定め、③で複数の手段を比べる。 |
| 任せる前に、目的・条件・範囲を示す | 未決定のことを渡さなければ、作る側がその空白を埋める。出力ができても、採用の根拠までは得られない。 | 全条件を最初から知る必要はない。不明点を明示し、②で守ること、④で調べることを残す。 |
| 追加する道具の維持にも手間がある | 入力先、修正箇所、覚える操作が増えると、目的以外に使う時間が生まれる。 | 同期や自動化で負担が減ることもある。③では追加案と現状維持の両方の負担を比べる。 |
| 替えやすさは大きさだけで決まらない | 小さいものでも、ほかの情報や人がその動きに頼っていると、変更の影響が広がる。 | 依存を調べて確認する費用も必要。削除を一律に勧めず、②で残すものと③で引き受ける負担を考える。 |
| 確認項目も目的に照らして見直す | 動作が正しくても、利用者に必要な使い方を確認項目から落としていることがある。 | 紙での確認と実利用の結果を区別する。④で次の試行と見直し条件を作り、その理由を残す。 |

補足56〜57頁のWunderlistの置き換えと教育ソフトウェアの再開発は、Fowlerが書籍で述べている経験の要約です。講演者自身の経験として語らず、一件の経験から失敗の頻度を推定しません。補足51頁のイベント運営の例はKaiserの書籍の説明用事例です。学生の教材・予定表・Aさんの相談は、本ワークショップの架空例として区別します。

## 題材の準備

参加者には紙と筆記具、またはメモアプリを用意してもらいます。発表は任意です。個人の事情や失敗を話すことを参加条件にせず、名前などは伏せて構いません。ワークの途中で共通事例へ切り替えてもらっても構いません。

### 自分の経験を使う場合

最近、新しい道具を使うか、教材を買うか、活動を引き受けるかなどを選んだ場面を一つ選びます。選択済みでも、迷っている途中でも扱えます。一度に生活全体を見直そうとせず、一つの出来事と選択に絞ります。

当時知っていたことと、後から分かったことを分けます。後から考えた別案は、その旨を記します。理由を思い出せない箇所は不明のまま残し、もっともらしい理由を創作しません。結果のよしあしだけで当時の判断を採点せず、次に似た場面で使える問いを持ち帰ります。

### 主催者が共通事例を用意する場合

事例は、学生が専門知識なしで一分程度で読める長さを目安にします。少なくとも次の材料を含めます。

1. 誰が、いつ、何をしようとしていたか。
2. 何を選ぼうとしているかと、そのきっかけとなる出来事。
3. すでに使えるもの、うまくいっていること。
4. 選ぶ際に守る条件と、まだ分からないこと。

最初から一案を正解にせず、異なる負担を引き受ける二案以上を考えられる事例にします。理由を考えるのに不可欠な事実を、後出しの答え合わせとして隠さないでください。実話を使うなら公開できる範囲を確認し、架空の人物・発言ならその旨を明示します。

スライド33には、そのまま使える架空事例を載せています。Aさんは課題用に新しい通知アプリを入れるか迷っていますが、先週は締切を知っていても最初にやることを決められませんでした。既存のメモとカレンダーがあり、課題名・正しい締切を残し、提出先は大学の授業サイトを使う条件があります。

別の共通事例を配る場合は、スライド33の代わりにその配布資料を読みます。スライド37・38・40・43〜45のAさんの記入例は参考例として扱えます。題材を統一したい場合は、それらの例も配布事例に合わせます。問い、四欄、持ち時間は共通です。説明用に設けた仮定を、実際の出来事と混ぜないでください。

## 60分の進行

時間には説明、読む時間、記入、確認を含めます。これは進行上の割り当てであり、参加者を対象に実測した所要時間ではありません。

| 時間 | スライド | 進め方 |
| --- | --- | --- |
| 0〜24分 | 1〜31 | AIによる試作を入口に、身近な例で四つの問いを説明する。ワークはまだ始めない。 |
| 24〜32分 | 32〜35 | 題材選択・説明3分、①記入4分、事実と推測の確認1分。 |
| 32〜40分 | 36〜38 | 説明と記入例2分、②記入4分、目的と条件の確認2分。 |
| 40〜48分 | 39〜41 | 説明と比較例2分、③比較・記入4分、選ぶ理由の確認2分。 |
| 48〜56分 | 42〜45 | 説明1分、メモの読み直し2分、条件の変更を考える2分、次の試行を書く3分。 |
| 56〜60分 | 46〜48 | 振り返り2分、希望者の共有とまとめ2分。共有は一人30秒を目安にする。 |

説明部分は、0〜3分に1〜4頁、3〜8分に5〜11頁、8〜14分に12〜18頁、14〜18分に19〜22頁、18〜24分に23〜31頁を目安にします。一頁では、示した例と問いを一つ扱います。ページが替わるたびに書籍の紹介や別の例を口頭で足さず、例の続きをたどってください。6・16・24・30頁では、事実と推測、予定と結果、完成と実利用、選択とその前提の違いを確認してから進みます。24分でワークへ移れるか、開催前のリハーサルで確認してください。

ワーク②と③では、指示と記入例を説明してから、記入中はスライド36または39へ戻します。次のページがあることを理由に記入時間を削らないでください。ワーク①で題材を決めにくい人には共通事例を案内します。

補足の49〜61は持ち帰り用で、60分の本編には含めません。49は三冊の案内、50〜55は概念の説明、56〜57は書籍の著者の経験、58〜60は共通事例とAIへの依頼の発展例、61は参考文献です。質問が長くなったらメモに残し、本編後に扱います。共有の希望者がいなければ、その時間をまとめに使います。

### ① 場面を具体的にする

「何を選ぶか」に加え、選択が必要になった出来事を書いてもらいます。「やる気がない」などの性格の評価を、出来事の代わりにしません。共通事例では、先週の通知は見ていたこと、最初にやることを決められなかったことが材料です。通知が普段から役立たないことや、本人が説明を理解できていないことまでは分かりません。

### ② 比較の基準を作る

「便利にする」で止まる場合は「いつ、何ができるようになれば助かるか」を聞きます。目的を一つに絞り、確かめる手がかりを一つ、守る条件を一つか二つ書いてもらいます。共通事例なら「最初にやることを選べる」が候補ですが、ほかの目的も、事例のどこを根拠にしたか説明できれば扱えます。

「守る条件」は、その題材に必要なものです。Aさんの課題名や締切を、個人の別の題材にも一律に要求しません。すでに役立っているものを、単に減らすために失わないよう確認します。

### ③ 効果と負担を一緒に比べる

二案を並べ、一つは今あるものを使う案や、小さく試す案にします。現状維持にも困りごとが残る負担があります。追加する案だけに負担を挙げ、今のままの案を無条件によいものとして扱わないでください。

目的への効果が不明なら「未確認」と記します。必須条件を満たさない案は、その条件を満たす工夫と負担まで考える必要があります。仮の案を選び、今は増やさないものと理由を残します。必要な追加を選ぶことも成果です。判断材料が足りなければ、保留する理由と次に調べることを書けます。

### ④ 確かめたことと、これから試すことを分ける

49〜51分は、場面、目的、案がつながっているか読み直します。51〜53分は、関係する条件を一つ変えてみます。使える時間が半分になる、予算が減るなど、参加者の題材に合う仮定を使います。共通事例の「課題の説明を外部のAIサービスへ入力できない」はこの段階だけの仮定で、特定の大学の方針ではありません。

53〜56分は、いつ、誰が、何を試し、何を見たら案を見直すかを書きます。自分のメモを読むだけで、実際に役立ったとは言えません。共通事例は架空なので、Aさんの反応は創作せず、試す計画までを成果にします。過去の結果が分かる参加者には、結果を追記してもらい、その差をすべて選んだ案の効果にはしないよう促します。

## 共通事例の記入例

一つの仮案であり、参加者に同じ答えを求めるものではありません。

| 欄 | 記入例 |
| --- | --- |
| ① 場面 | 前日の夜、締切は知っていたが最初にやることを決められず、画面を閉じた。資料の説明がどのくらい具体的だったかは不明。新しい通知アプリを入れるか迷っている。 |
| ② 目的と条件 | 課題を開いたとき、最初にやることを一つ選べるようにする。選べた行動と、迷った箇所を聞いて確かめる。課題名と正しい締切の日付・時刻は残し、提出先も変えない。 |
| ③ 選択肢 | Aは今のメモに最初の一つを書く。考える手間は残る。BはAIで候補を出し、本人が確認する。説明の入力と候補の確認が要る。まずAを試す。追加通知は、この場面への必要性が未確認なので見送る。既存の通知は消さない。 |
| ④ 確かめ方 | 書く内容自体に迷う点は未解決。外部のAIへ入力できない仮定でもAは試せる。次の課題でAさんに一行書いてもらい、取りかかれたか、どこで迷ったかを聞く。書く内容で止まるなら、説明や相談の助け方を考え直す。実施前なので効果は未確認。 |

メモを描けたことと、課題に取りかかれたこと、提出が間に合ったことは異なる結果です。確かめた範囲を広げて表現しないでください。
