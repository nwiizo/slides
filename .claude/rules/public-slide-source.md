# 公開するスライド原稿

Markdown、HTMLコメント、関連ドキュメントも公開物として扱う。

- HTMLコメントに、依頼の経緯、修正理由、採用しなかった案、AIへの指示、レビュー履歴、個人のローカルパスなどの制作事情を残さない。見えない注釈へ退避することもしない。
- HTMLコメントは、背景・配色・クラスなどMarpの表示に必要なディレクティブに限る。
- 聴衆へ伝えたい主張、理由、前提、留保はスライド本文に書く。口頭説明や非表示ノートだけに置かない。枚数を増やして分割し、必要なら文字サイズを調整して、実際のPDFで可読性を確かめる。
- 出典は公開できる書誌やURLとして、本文の図の近くや参考文献ページに置く。制作過程の資料名や確認履歴を引用に混ぜない。
- 講演の早い段階に、何を話すかがわかる目次を置く。指定された自己紹介・書籍紹介の順序は保つ。
- 本文、図、比較、フローなど繰り返し使う見た目は共通テーマへ実装する。スライドごとの `style: |` でテーマを上書きし続けない。
- 共通テーマへレイアウトを追加するときは、必要に応じてクラスで利用範囲を指定し、既存資料への影響を実ビルドで確かめる。2026年の読み返せる本文レイアウトは `theme: 3shake-2026-presentation` と `class: reading` を使う。

公開前には対象MarkdownのHTMLコメントと、同時に追加するドキュメントも読み、制作事情が残っていないことを確認する。

## 構造を説明するSVG図のスタイル

概念の関係、境界、反復、移行前後の変化を説明するときは、編集可能なSVGを用いる。基準になる例は `assets/images/2026/technical-debt-in-the-ai-era/replaceable-implementation.svg`。図の中に対象と関係を置き、本文ではその理由・条件・判断への影響を説明する。

- 単純な図はSVGを直接記述する。`rect`、`path`、`text`、矢印の`marker`を中心に組み立て、一度限りの生成スクリプトや依存を追加しない。
- 横長の図は `viewBox="0 0 1120 300"` 前後を起点に、必要な高さへ調整する。スライドでは `<img width="1100" src="...svg" alt="関係の説明">` で配置し、講演固有のSVGを `assets/images/{year}/{talk}/` に置く。
- 白とグレーを基本にする。背景は `#f5f5f5`、強調する領域は `#e0e0e0`、線は `#999` または `#666`、文字は `#222`、補助説明は `#555` を目安にする。色だけで状態や違いを伝えない。
- 角丸の箱、2〜3px程度の線、揃えた余白を使う。日本語フォントは `Noto Sans JP, Hiragino Sans, sans-serif`。幅1120の図では主要ラベルを26〜30px、補助説明を22〜25px程度から調整し、箱と文字の間に余白を残す。
- 箱は対象や境界、矢印は依存・処理の順序・フィードバックなどを表す。何の関係かをラベルや本文で明示する。循環は戻る線を描き、線を説明文字に重ねない。分けた箱だけで独立性を主張しない。
- 図は一つの主張を支える範囲に絞る。本文の箇条書きをすべて箱へ移すだけの図にはせず、図にした関係を本文で掘り下げる。
- SVGに `role="img"`、`title`、`desc`、それらを指す `aria-labelledby` を付け、埋め込む `img` にも関係を説明する `alt` を書く。外部フォント・外部画像への依存やスクリプトを入れない。
- 本文を小さくするときは、まず共通テーマの `small` など既存クラスを使う。`style: |` で上書きせず、図と本文の役割を整理し、それでも過密なら分割する。
- HTMLとPDFを実ビルドし、変更したページを画像で開いて確認する。ラベルのはみ出し、矢印と文字の交差、脚注・ロゴとの重なりを直す。SVG単体の見た目だけで完了にしない。
- 自作の整理図と、書籍から引用する原図を区別する。引用図を自作図のように扱わず、必要な出典・権利表示を残す。
